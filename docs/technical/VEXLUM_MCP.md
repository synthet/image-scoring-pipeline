# vexlum: single MCP + CLI entry point

**Authority:** Python core [`modules/vexlum/`](../../modules/vexlum/), TS host [`mcp-server/src/vexlum.ts`](../../mcp-server/src/vexlum.ts), REST overrides [`mcp/vexlum/rest_overrides.yaml`](../../mcp/vexlum/rest_overrides.yaml). Issue [#758](https://github.com/synthet/image-scoring-pipeline/issues/758).

`vexlum` replaces the separate backend MCP surfaces (`is-be-mcp`, `is-be-live`, the full ~54-tool stdio server, the router and proxy servers, and the `MCP_TOOL_PROFILE` servers). Those still start, but they log a deprecation warning and serve the vexlum tools. See [Deprecated surfaces](#deprecated-surfaces).

## Tools

| Tool | Purpose |
|------|---------|
| **`search(query, limit=10, source?, category?, tier?, include_schemas=false)`** | Ranked catalog search (BM25 plus aliases and intent examples; optional Jev rerank when confidence is low). An empty query lists actions that match the filters. |
| **`resolve(action_id)`** | Full contract for one action: input schema, tier, `requires`, executor, an example call and the equivalent CLI line. Also accepts legacy tool names, old `dispatch` ids, REST `operationId`s and `"METHOD /path"`. |
| **`execute(action_id, arguments={}, dry_run=false, confirmed=false, confirm_token?, request_id?)`** | Validates arguments against the schema, applies the [tier policy](#tier-policy) and runs the action. |

Deprecated aliases are still listed unless `VEXLUM_HIDE_DEPRECATED=1` is set on the TS host: `dispatch` behaves like `execute` and adds a `warnings[]` entry, and `sse_status` behaves like `execute("system.status")`.

### Workflow

```text
search("why did scoring fail")                       -> diagnostics.get_error_summary, ...
resolve("diagnostics.get_error_summary")             -> schema, tier=read, example
execute("diagnostics.get_error_summary", {})
execute("db.query", {"query": "SELECT count(*) FROM images"})
```

Every `execute` returns one envelope: `status`, `action_id`, `request_id`, `source`, `tier`, `dry_run`, `summary`, `data`, `warnings`, `notes`. Errors return `status: "error"` with a `code` (for example `unknown_action`, `validation_error`, `confirmation_required`, `confirm_token_invalid`, `http_error`) and `details`. Unknown ids include `suggestions`.

**REST inputs:** path parameters and query parameters are top-level arguments, and the JSON request body goes in `body`. The base URL is resolved in this order: `VEXLUM_API_URL`, then the origin of `IMGSCORE_WEBUI_MCP_SSE_URL`, then the port in `webui.lock`, then `http://127.0.0.1:7860`. `X-API-Key` comes from env `API_KEY` or `config.json` `api.key` and is never echoed. Responses larger than `VEXLUM_MAX_RESPONSE_BYTES` are truncated and marked `truncated: true`.

**DB inputs:** `db.query` accepts a single read-only `SELECT`/`WITH` statement, `params` (positional `%s`) and `max_rows`; it uses the same forbidden-pattern checks as `execute_sql`. `db.execute` runs one write or DDL statement in one transaction. Its dry run executes the statement and **rolls back**, reporting `rowcount` and any `RETURNING` rows.

## Tier policy

| Tier | Examples | Requirement for a real run |
|------|----------|---------------------------|
| `read` | diagnostics, `GET` API, `db.schema`, `db.query`, browser snapshot | none |
| `write` | run jobs, `POST`/`PUT`/`PATCH` API, `set_image_metadata`, `set_config_value`, browser click/type | `confirmed=true` |
| `destructive` | `db.execute`, `DELETE` API, `prune_missing_files`, `rebase_file_paths`, `execute_code` | env `VEXLUM_ALLOW_ELEVATED=1` on the vexlum process, **and** a prior `dry_run=true` that returned `data.confirm_token`, **and** `confirmed=true` with that token |

- `dry_run=true` never mutates and is always allowed. Actions with a native preview (for example `db.execute`, `prune_missing_files`) run it; others return the validated arguments and the call that would be made.
- The default tier for a REST operation follows its HTTP method. [`rest_overrides.yaml`](../../mcp/vexlum/rest_overrides.yaml) corrects operations where the method is misleading, for example `POST …/preview` endpoints are `read`.
- `confirm_token` is `<expiry>.<hmac>` over the action id, canonical arguments and expiry. It is valid for 10 minutes, and changing any argument invalidates it. The key comes from `VEXLUM_TOKEN_SECRET`, otherwise from `~/.vexlum/confirm.key` (override the path with `VEXLUM_TOKEN_KEY_FILE`), so a CLI dry run can be confirmed by a later CLI call.
- Every write or destructive execute is logged with action id, request id, tier and duration. Argument values are not logged.

Destructive example:

```text
execute("db.execute", {"query": "DELETE FROM jobs WHERE id = %s", "params": [123]}, dry_run=true)
  -> data.rowcount, data.confirm_token
execute("db.execute", {"query": "DELETE FROM jobs WHERE id = %s", "params": [123]},
        confirmed=true, confirm_token="<from dry run>")
```

## Setup

### MCP client

Build the host once: `cd mcp-server && npm ci && npm run build`. Then register one stdio server, as in [`.cursor/mcp.example.json`](../../.cursor/mcp.example.json):

```json
{
  "mcpServers": {
    "vexlum": { "command": "node", "args": ["mcp-server/dist/vexlum.js"], "cwd": "<repo root>" }
  }
}
```

The Node host starts the Python worker (`python -m modules.vexlum worker`) as soon as it launches, so the catalog warms in the background.

| Host env (`VEXLUM_*`, falling back to the old `IS_BE_MCP_*`) | Effect |
|------|--------|
| default on Windows | `docker exec -i -w /app image-scoring-gpu-shell python -m modules.vexlum worker` |
| `VEXLUM_GPU_SHELL` | Container name instead of `image-scoring-gpu-shell` |
| `VEXLUM_USE_WSL=1` | Run the worker in WSL with `VEXLUM_VENV_ACTIVATE` (default `~/.venvs/tf`) |
| `VEXLUM_WORKER_SHELL` | Custom `bash -lc` command line |
| `VEXLUM_HIDE_DEPRECATED=1` | List only `search`, `resolve`, `execute` |
| `MCP_PLAYWRIGHT_HEADED=1` | Show the browser for `browser.*` actions, for example for a manual login (default: headless) |

`VEXLUM_ALLOW_ELEVATED`, `VEXLUM_API_URL`, `VEXLUM_MAX_RESPONSE_BYTES`, `VEXLUM_TOKEN_SECRET` and `MCP_PLAYWRIGHT_ENABLED` are forwarded into gpu-shell. Set them on the MCP server entry, not inside the container.

Claude Code: `.claude/settings.json` allows `mcp__vexlum__search` and `mcp__vexlum__resolve`. `execute` is left out on purpose, so writes still prompt.

### WebUI SSE

The WebUI mounts the same three tools at `/mcp/sse` (port 7860). `GET /mcp-status` reports `server: "vexlum"`. `MCP_SSE_PROFILE=full` still restores the legacy ~54-tool SSE surface and logs a deprecation warning.

### Catalog cache

The catalog is snapshotted to `~/.vexlum/cache/catalog-<fingerprint>.json`; the fingerprint covers the source files (registry, overlay, `openapi.yaml`, overrides). A cold build takes about 16 s and a cached search about 1 s. `VEXLUM_CACHE_DIR` moves the cache and `VEXLUM_CATALOG_CACHE=0` disables it.

## CLI

Two front ends share the same commands:

- `scripts\vexlum.cmd …` (Windows) or `node mcp-server/dist/vexlum.js …`: runs through the TS host, so `browser.*` works too. With no command it runs the stdio MCP server.
- `python -m modules.vexlum …`: Python only, in gpu-shell or a full venv; no `browser.*`.

```text
vexlum search QUERY [--source tool|api|db|browser|system] [--category C] [--tier T] [--limit N] [--schemas]
vexlum resolve ACTION_ID
vexlum exec ACTION_ID [--args JSON | --args-file PATH] [--dry-run] [--confirm] [--token T] [--request-id ID]
vexlum list [--source S] [--category C] [--tier T]
vexlum status                     # catalog counts, DB, REST API and SSE reachability
python -m modules.vexlum mcp      # stdio MCP server without the TS host
python -m modules.vexlum worker   # JSONL worker used by the TS host
```

`--json` (before the command) prints raw envelopes. Exit codes: 0 success, 1 action error, 2 usage error.

```text
scripts\vexlum.cmd status
scripts\vexlum.cmd search "why did scoring fail"
scripts\vexlum.cmd exec api.health.health_check
scripts\vexlum.cmd exec db.query --args "{\"query\":\"SELECT count(*) FROM images\"}"
scripts\vexlum.cmd exec db.execute --args-file stmt.json --dry-run
```

## Deprecated surfaces

| Old entry point | Now |
|-----------------|-----|
| `is-be-mcp` (`mcp-server/dist/compactIndex.js`) | Shim that serves the vexlum tools |
| `is-be-live` (`/mcp/sse` compact profile) | Serves the vexlum tools |
| `python -m modules.mcp_server` (stdio) | Warns, then starts `modules.vexlum.mcp_stdio`. `VEXLUM_LEGACY_FULL_STDIO=1` restores the old full stdio server until removal |
| `modules/mcp/router_server.py`, `modules/mcp/proxy_server.py` | Warn, then start vexlum |
| `scripts/mcp/compact_worker.py` | Delegates to the vexlum worker |
| `scripts/batch/run_mcp_*.bat` | Print a deprecation notice; the Python entry points they start now run vexlum |
| `MCP_TOOL_PROFILE=…` | Honored only by the legacy full surfaces (`MCP_SSE_PROFILE=full`, `VEXLUM_LEGACY_FULL_STDIO=1`) |

The old [search + dispatch contract](MCP_SEARCH_DISPATCH.md) still describes `dispatch` ids and envelopes, which vexlum accepts.
