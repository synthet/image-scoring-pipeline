## The two API gates are not redundant

They chain, and either one alone leaves a hole:

```
modules/api/routers/  ──api-contract──>  openapi.json  ──api-types──>  electron/apiTypes.ts
```

`api-types` only proves the second arrow. Before `api-contract` existed, a route added to a
router reached neither the spec nor the gallery's generated types, and nothing failed. Both
arrows are regenerated by:

```bash
python scripts/export_openapi.py     # code    -> openapi.json
npm run api:types:generate           # openapi.json -> electron/apiTypes.ts
```

`api-contract` compares **route sets** (`METHOD /path`), not full schemas, so response-model
edits do not fail it — `api-types` catches those.

### Advisory artifacts

`docs/reference/api/openapi.yaml` and `docs/reference/api/openapi.json` have no generator
wired up and are reported but **not** enforced. Run `python scripts/ci/contract_check.py --strict`
to gate on them too.

## Reproducing locally

Windows (`.venv`) or WSL (`~/.venvs/tf`) both work — the gates avoid the ML stack:

```bash
./scripts/ci/run_fast_smoke_tests.sh          # backend-pytest-fast
python scripts/ci/contract_check.py           # api-contract
npm run api:types:check                       # api-types
```

CI installs [`requirements/requirements_ci.txt`](../../requirements/requirements_ci.txt) — seven
packages, no TensorFlow or Torch, because nothing in the blocking path imports them.

## Why the smoke slice is curated

The documented fast subset is green but unsuitable as a required gate:

| Slice | Tests | Time | Deps |
|-------|------:|-----:|------|
| `scripts/ci/run_fast_smoke_tests.sh` | 63 | ~13 s | `requirements_ci.txt` |
| `-m "not gpu and not db and not ml and not firebird"` | 2147 passed, 290 skipped | ~13 min | Full ML stack |

The broad subset runs in the coverage workflow instead. When you add a test file that guards a
security, config or dispatch invariant, add it to the smoke script.
