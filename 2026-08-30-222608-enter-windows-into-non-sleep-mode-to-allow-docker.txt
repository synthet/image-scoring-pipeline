     Make bird bbox a first-class part of the bird_species phase

     Context

     The ask: guarantee that bird bounding-box detection is part of the
     "birding" phase by default, including when the library is driven from
     Dashboard → Drive to Complete (/ui/dashboard).

     What's already true (verified live, 2026-08-30):

     - There is no phase named birding. The phase is bird_species
       (modules/phases.py:38, sort_order 60, optional: true, requires keywords).
     - Bbox detection already runs inside the phase by default.
       BirdDetector.enabled defaults to True (modules/bird_detection.py:105);
       config.json has no bird_detection section, so the code defaults apply.
       ultralytics 8.4.120 and the cached synthet/bird-detect-v0 weights are
       both present in image-scoring-webui.
     - Drive to Complete already includes it. The default preset is full →
       FULL_PIPELINE_STAGE_CODES (frontend/src/constants/pipeline.ts:4) which
       ends in bird_species; server-side _DRIVE_STATE["target_phases"] = None →
       full pipeline (modules/runs_autodrive.py:2025).
     - Live DB: 20,422 real boxes, 14,330 "no bird" sentinels, 3 decode errors,
       0 classified images missing a bbox, 93 bird-tagged images still pending
       classification.

     The actual problem: bbox is a side effect of classification, invisible to
     every completeness check.

     1. get_phase_incomplete_sql("bird_species")
        (modules/db_legacy.py:10064-10086) and is_image_bird_species_complete
        (modules/db/__init__.py:19-70) test only "has a species:* keyword" or
        "has the exhausted marker". bird_bbox is never consulted.
     2. So an image that is species-complete (or exhausted) but has bird_bbox IS
        NULL, or a transient {"detected": false, "error": 
        "detector_unavailable"} sentinel, is permanently invisible to Drive.
        Only scripts/backfill_bird_bbox.py can repair it.
     3. BIRD_SPECIES_RUNNER_VERSION was never bumped when bbox persistence was
        added (modules/bird_species.py:20), so every pre-bbox done row stays
        done forever.

     Intended outcome: a bbox gap is real, visible work. The folder shows
     awaiting_bird_species, Drive enqueues it, and the runner repairs it with a
     detector-only pass — no BioCLIP re-run, no keyword rewrites — so the state
     converges instead of looping.
